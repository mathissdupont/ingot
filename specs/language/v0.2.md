# Ingot Language Specification, version 0.2

Status: **Draft, partially implemented**. Normative for the `0.2` language
version where this document defines behaviour. Language 0.2 inherits Language
0.1 except where this document explicitly says otherwise.

Implemented in this draft:

* project-local imports for shared `type`, `tool` and `verifier` declarations.

Not yet implemented from the Language 0.2 roadmap:

* optional and union values;
* pure user-defined helper functions;
* any decision on generics.

---

## 1. Imports

Imports make reusable declaration files possible without adding runtime effects
or package-registry semantics.

```ingot
language 0.2
package heptapus.examples.research

import "./shared/web.ing" {
  type search_result
  tool web.search
  verifier CitationCheck
}
```

An import declaration appears after `language` and optional `package`, and before
all `type`, `tool`, `verifier` and `agent` declarations.

Import paths are plain string literals. `${...}` interpolation is rejected.

The path must:

* be relative;
* end in `.ing`;
* contain only normal path segments plus optional `.`;
* not contain `..`;
* not be absolute.

The compiler resolves paths relative to the importing file's directory. Virtual
in-memory sources cannot resolve imports.

## 2. Imported items

An import block contains explicit items:

```ebnf
import-decl  = "import" , STRING , "{" , { import-item , [ "," ] } , "}" ;
import-item  = "type" , IDENT
             | "tool" , dotted-name
             | "verifier" , IDENT ;
```

Only these declaration kinds may be imported. Agent imports, wildcard imports
and re-exports are not part of Language 0.2.

Imported declarations participate in the same name resolution, type checking,
tool-grant checks, effect checks and policy checks as local declarations.
Declaring or importing a tool still grants nothing; an agent must list it in its
own `tools` block and must still satisfy the relevant `policy` rules.

Duplicate local/imported declarations are rejected by the existing duplicate
declaration rule.

## 3. IR impact

Imports are compile-time syntax. They are erased before lowering.

Agent IR remains version `0.1`; the emitted agent's `language` field is the
source language version, for example `"0.2"`.

## 4. Diagnostics

Import resolution failures use `ING2018`. This includes invalid paths,
unreadable targets, missing imported items and import cycles.

Using `import` in a `language 0.1` source is rejected with `ING1020`.

## 5. Formatter and editor behaviour

The canonical formatter prints imports after `package` and before declarations:

```ingot
language 0.2
package demo

import "./shared.ing" {
  type shared
}
```

Editor integrations should treat `import` as a keyword. When a file is compiled
from disk, diagnostics and declaration locations may refer to imported files in
the same source map.
