# Ingot Language Specification, version 0.2

Status: **Draft, partially implemented**. Normative for the `0.2` language
version where this document defines behaviour. Language 0.2 inherits Language
0.1 except where this document explicitly says otherwise.

Implemented in this draft:

* project-local imports for shared `type`, `tool` and `verifier` declarations.
* optional and union type expressions.
* expression-only pure helper functions.
* a declared reach on a tool's effects, checked against the agent's policy.
* verifier bodies, which make a `verify` a check that runs.

Deferred from the Language 0.2 roadmap:

* generic type parameters and generic helper functions. See
  [RFC-0011](../../rfcs/0011-language-v0.2-generics-decision.md).

---

## 1. Imports

Imports make reusable declaration files possible without adding runtime effects
or package-registry semantics.

```ingot
language 0.2
package heptapus.examples.research

import "./shared/web.ing" {
  type search_result
  tool web.search
  verifier CitationCheck
}
```

An import declaration appears after `language` and optional `package`, and before
all `type`, `tool`, `verifier` and `agent` declarations.

Import paths are plain string literals. `${...}` interpolation is rejected.

The path must:

* be relative;
* end in `.ing`;
* contain only normal path segments plus optional `.`;
* not contain `..`;
* not be absolute.

The compiler resolves paths relative to the importing file's directory. Virtual
in-memory sources cannot resolve imports.

## 2. Imported items

An import block contains explicit items:

```ebnf
import-decl  = "import" , STRING , "{" , { import-item , [ "," ] } , "}" ;
import-item  = "type" , IDENT
             | "tool" , dotted-name
             | "verifier" , IDENT ;
```

Only these declaration kinds may be imported. Agent imports, wildcard imports
and re-exports are not part of Language 0.2.

Imported declarations participate in the same name resolution, type checking,
tool-grant checks, effect checks and policy checks as local declarations.
Declaring or importing a tool still grants nothing; an agent must list it in its
own `tools` block and must still satisfy the relevant `policy` rules.

Duplicate local/imported declarations are rejected by the existing duplicate
declaration rule.

## 3. IR impact

Imports are compile-time syntax. They are erased before lowering.

The current compiler emits Agent IR `0.2`; the emitted agent's `language` field
is the source language version, for example `"0.2"`.

## 4. Diagnostics

Import resolution failures use `ING2018`. This includes invalid paths,
unreadable targets, missing imported items and import cycles.

Using `import` in a `language 0.1` source is rejected with `ING1020`.

## 5. Formatter and editor behaviour

The canonical formatter prints imports after `package` and before declarations:

```ingot
language 0.2
package demo

import "./shared.ing" {
  type shared
}
```

Editor integrations should treat `import` as a keyword. When a file is compiled
from disk, diagnostics and declaration locations may refer to imported files in
the same source map.

## 6. Optional and union type expressions

Language 0.2 adds nullable and closed-union type expressions.

```ingot
type page {
  title: string?
  body: markdown | text
}

tool web.fetch(url: string) -> page? !network
```

`T?` means the value may be `T` or absent/null. `A | B` means the value is one
of the listed alternatives.

Postfix `[]` and `?` bind tighter than `|`:

```ingot
items: string?[]
maybe_items: string[]?
attachments: (file | bytes)[]
```

Assignability is conservative:

* `T` is assignable to `T?`;
* `T?` is not assignable to `T` without a future narrowing construct;
* `A | B` is assignable to expected type `E` only when both `A` and `B` are
  assignable to `E`;
* a value is assignable to expected union `A | B` when it is assignable to at
  least one alternative.

These type forms are represented in Agent IR as canonical type strings.

## 7. Pure helper functions

Language 0.2 adds top-level pure helper functions:

```ingot
fn bump(n: int) -> int = n + 1
```

A helper body is a single expression. It may use parameters, literals, lists,
field reads, builtin pure functions, and unary/binary operators. It may not use
agent work such as `ask` or `call`.

Helper calls are expression forms:

```ingot
next = bump(count)
other = bump(n: count)
```

Arguments may be positional or named and are checked against the helper's
declared parameter list. The body type must be assignable to the declared return
type.

Helpers are compile-time source structure. They lower by inlining the helper
body with the lowered argument values, so no helper declaration or helper-call
node appears in Agent IR. Helper calls consume no step budget.

In the first implementation slice, helper bodies may not call other helpers.
That keeps recursion and helper composition out of the static-bounds model until
they are specified separately.

## 8. Deferred generics

Language 0.2 intentionally does not add generic type parameters or generic
helper functions.

Generics are deferred until at least three real `.ing` source examples show the
same reusable type or helper pattern that cannot be expressed cleanly with
imports, optional types, union types and pure helper functions.

This keeps Language 0.2 focused on observed agent-authoring friction rather than
adding a general-purpose type-system feature before its use is clear.

## 9. A capability's reach

Language 0.1 gives a tool a list of effect **kinds** and an agent a policy that
grants them. It has no way to say *where* an effect goes at the call site, so
`network allow ["arxiv.org"]` is a claim the compiler cannot compare against
anything. This section adds the other half. See
[RFC-0014](../../rfcs/0014-a-capabilitys-reach.md).

### 9.1 Syntax

An effect on a tool declaration MAY carry the values it reaches:

```ingot
tool web.search(query: string) -> search_result[] !network("arxiv.org")
tool repo.read(path: string)   -> string          !filesystem_read("src", "docs")
tool page.fetch(url: string)   -> string          !network
```

The parenthesised list is the effect's **reach**. Parenthesised rather than
bracketed, so a tool's declaration does not read like a policy rule: the two
mean different things, and reading alike would invite checking only one of them.

An effect written without parentheses declares no reach. That is Language 0.1's
syntax and it keeps Language 0.1's meaning.

### 9.2 Values

A reach uses the same vocabulary [Language 0.1 §7.1](v0.1.md) defines for a
policy of the same subject:

| Effect | A value is | Rules |
|---|---|---|
| `network` | a host name | matched exactly; no wildcards, no URL |
| `filesystem_read` | a workspace-relative path | not absolute, no `..` |
| `filesystem_write` | a workspace-relative path | not absolute, no `..` |

`external_write`, `secret_access` and `model_access` name no resource and MUST
be refused with parentheses (`ING4010`). A value language invented for them here
would be a second policy syntax nobody documented.

An empty reach — `!network()` — MUST be refused (`ING4010`). It reads like
"reaches nothing", which describes a tool that does not need the effect.

A value that breaks a rule in the table MUST be refused (`ING4010`) rather than
narrowed or normalised. A path that means something different on two machines
would make the check in §9.3 a comparison against a moving target.

Values are sorted and deduplicated by the compiler, so the canonical encoding is
a property of the document rather than of whoever wrote the declaration.

### 9.3 Containment

For each tool an agent grants, for each of that tool's scoped effects:

| Policy for that effect | Rule |
|---|---|
| `allow` with values | every declared value MUST appear in the policy's list, or `ING4009` |
| `allow` with no values | the grant is unbounded and contains any reach |
| `require approval` with values | as `allow` with values; the gate is about *whether*, not *where* |
| `deny`, or no rule | already `ING4001` or `ING4007`; reach is not considered |

A tool that declares no reach is not checked and is not an error.

`ING4009` MUST name both the declared value and the policy that does not grant
it. The two halves of the mistake are in different declarations and either one
may be the wrong one.

A sub-agent's tools are checked against the sub-agent's own policy, and a
parent's grant MUST contain the union of what it delegates — the rule
[Language 0.1 §7](v0.1.md) already applies to effect kinds, extended to values.

### 9.4 IR

A tool binding gains `scopes`, mapping an effect name to its sorted values:

```json
{
  "ref": "mcp:web.search",
  "effects": ["network"],
  "scopes": { "network": ["arxiv.org"] }
}
```

Omitted when the tool declares no reach, so an artifact that uses none encodes
exactly as it did before and no package digest moves. Every key of `scopes` MUST
also appear in `effects`.

### 9.5 What a runner must do

A declared reach is a stronger statement than a policy value, and the two are
treated differently on purpose.

A policy's value list is advisory wherever nothing enforces it, and Ingot says
so: `ingot sandbox` reports what a boundary cannot deliver, and
`--sandbox-allow-unenforced` acknowledges it.

A declared reach is not advisory. Per [Runtime 0.1 §2](../runtime/v0.1.md), a
backend that cannot honour it MUST refuse:

> A run MUST refuse to start when the artifact declares a reach the arrangement
> cannot enforce, unless the operator explicitly acknowledges it.

The refusal MUST happen before any tool server is started and before any model
is called. The reference CLI acknowledges with `--allow-unenforced-scopes` and
names every declaration it is proceeding without.

Today no arrangement bounds egress to a host
([GAP-001](../../docs/gaps.md#gap-001)), so any declared `network` reach refuses
everywhere. A declared filesystem reach is kept under `--sandbox` and
`--contained`, whose mounts come from the policy that §9.3 proved contains it.

## 10. Verifier bodies

Language 0.1 declares a verifier as a name and a signature
([Language 0.1 §5.2](./v0.1.md)). That is enough to type-check a `verify` and
nothing more: the artifact names a property and carries nothing that tests it.

Language 0.2 lets a verifier carry the check:

```ingot
verifier MinSources(d: draft, min: int) = len(d.sources) >= min
```

```ebnf
verifier-decl = "verifier" , IDENT , params , [ "=" , expression ] ;
```

The body is a single expression whose type must be `bool`. There is no `->`,
because a verifier answers one question and `bool` is the only answer.

### 10.1 What a body may contain

The same subset as a helper body (§7): parameters, literals, lists, field reads
from parameter values, builtin pure functions such as `len`, and unary and
binary operators. It may also **call a `fn` helper** — §7 forbids
helper-to-helper calls, so inlining a helper into a verifier stays one level
deep and terminates by construction.

It may not use `ask`, `call`, `parallel map`, working memory, `emit`, or another
verifier.

This is not only about erasability. A verifier's outcome has to be reproducible
from the run record alone ([Runtime 0.4 §1](../runtime/v0.4.md)), and a body
that could reach outside the run would not be. A property that genuinely needs
to reach — resolving a URL, reading prose — belongs in a `tool` call, whose
result is a value the flow can then check.

### 10.2 Static semantics

Arguments at a `verify` site are matched against the verifier's parameter list
positionally or by name, unchanged from Language 0.1.

| Situation | Diagnostic |
|---|---|
| a body under `language 0.1` | `ING1020`, error |
| a body that is not pure | `ING2019`, error |
| a body whose type is not `bool` | `ING2020`, error |
| a `verify` of a verifier with no body | `ING6006`, warning |
| a `verify` whose argument was already emitted | `ING6007`, warning |

`ING6006` narrows: it now fires only for a bodyless verifier, because that is
the only case left in which nothing can be carried out.

`ING6007` is new, and it exists because a failed check ends the run
([Runtime 0.4 §2](../runtime/v0.4.md)) but cannot un-emit an artifact. A record
cannot be an artifact, so an `emit` normally takes a *field* of the value a
`verify` names; the warning fires when the emitted value's root binding is one
the `verify` checks.

### 10.3 IR and lowering

A verifier declaration does not appear in Agent IR. Its body is inlined at each
`verify` site as the node's `condition`, with the call's arguments substituted
for the parameters — the same substitution §7 specifies for helper calls. See
[Agent IR 0.2 §5](../ir/v0.2.md).

A verifier body consumes no step budget and no tokens. A `verify` node's static
cost is unchanged: the cost of its arguments.

### 10.4 Formatter

A body is printed on the declaration line, after `=`:

```ingot
verifier MinSources(d: draft, min: int) = len(d.sources) >= min
```

A verifier without one prints exactly as it did in Language 0.1.

This is opt-in strictness. An artifact written before this section declares no
reach and is unaffected.

## 11. Persistent memory

Language 0.1 has one memory lifetime. `working ephemeral` is discarded when the
run ends, and there is no way to say otherwise. This section adds the other
half. See [RFC-0018](../../rfcs/0018-state-that-outlives-a-run.md).

### 11.1 Syntax

A `memory` block MAY hold a `persistent` block beside its `working` one:

```ingot
memory {
  working ephemeral { draft: markdown }
  persistent { seen_urls: string[] = [], visits: int = 0 }
}
```

`persistent` is a sibling of `working ephemeral`, not a second lifetime after
`working`. A block that outlives the run is not working memory however it is
spelled.

`persistent` is **not a reserved word**. It appears in exactly one position, and
the reserved set is kept to words that do not.

### 11.2 The `memory` root

Persistent fields are addressed by `memory.`; ephemeral ones stay on `state.`.

```ingot
flow {
  memory.visits = memory.visits + 1
  state.draft = ask<markdown>("Visit ${memory.visits}.")
}
```

Both roots are usable anywhere a value is: in an expression, on the left of an
assignment, and inside a `${…}` prompt placeholder.

One root per store, rather than one root with the lifetime discoverable from the
declaration, because a write that outlives the run is a different act from a
write to a scratchpad and the reader of a flow should be able to tell which
without looking anything up.

### 11.3 Every persistent field declares an initial value

`= <literal>` is required. `ING3013` when it is missing.

Ephemeral state has a coherent "not yet written" state and reading it is an
error ([Runtime 0.1 §5](../runtime/v0.1.md)). Persistent state does not: the
first run has nothing and every later run has something. Declaring the starting
point once, in the type, is what removes a first-run guard from every use site.

The value MUST be a literal — a string without interpolations, a number, a
boolean, or a list of those. `ING3014` otherwise. The initial value is resolved
before any node executes, so there is nothing for an expression to read.

It is checked against the declared type like any other assignment. An empty list
is assignable to a list of any element type, which is what makes `= []` work.

### 11.4 Rules that carry over unchanged

* A write inside `parallel map` is refused (`ING7002`), exactly as an ephemeral
  write is, and for the same reason: iterations run concurrently.
* Reading a field that is not declared is `ING2006`. Where the name is declared
  in the *other* store, the diagnostic says so and names the root to use.
* A persistent write triggers **no effect**. See
  [RFC-0018](../../rfcs/0018-state-that-outlives-a-run.md) — the store is a
  resource the operator supplies, not a reach the artifact grants itself.

### 11.5 IR and lowering

A read of `memory.x` lowers to a `state.read` node and a write to `state.write`,
each carrying `scope: "memory"` — the same two node kinds, rather than a
parallel pair that would have to be kept in step with them. The declaration
itself becomes the document's `persistent` map. See
[Agent IR 0.2 §7](../ir/v0.2.md).

### 11.6 Formatter

A `persistent` block prints after the `working` one, one field per line, with
the initial value after `=`. An agent that declares none prints exactly as it
did in Language 0.1.
