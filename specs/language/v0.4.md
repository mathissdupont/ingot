# Ingot Language Specification, version 0.4

Status: **Draft, implemented**. Normative for the `0.4` language version where
this document defines behaviour. Language 0.4 inherits Language 0.3 except where
this document explicitly says otherwise.

Implemented in this draft:

* `else`, a value to use when an attempt fails.
* one new assignability widening, `string` → `text`, without which the feature
  above does not reach the program it was designed for.

Designed in [RFC-0022](../../rfcs/0022-a-failure-an-iteration-can-absorb.md).

---

## 1. `else`

An expression that can fail may state the value to use when it does:

```
writeup = call fs.read_file("${incident.id}.md") else "no write-up was filed"
```

`else` may follow exactly three things — an `ask`, a tool `call`, and a sub-agent
`call` — and the expression after it must be **pure**. Both sides have the same
type, by the ordinary assignability rule ([Language 0.1 §4.2](v0.1.md)).

That is the whole feature. Everything below is a consequence of the restriction.

### 1.1 Why a pure fallback, and what it buys

Three guarantees this language states over all paths rest on the fallback
reaching nothing.

**`steps` still bounds the work.** The attempt is the step, and it is charged
exactly once whether or not the fallback is used. A fallback is an expression, and
expressions are not steps, so the compiler's bounded walk of the graph
([Language 0.1 §8](v0.1.md)) does not branch and the number it proves does not
move.

**A policy still describes one sequence of nodes.** A policy is checked per node.
A fallback that could reach something would make *what this agent may reach* the
union over two paths, and an operator reading the policy would have to be told
which path they were reading. A pure fallback reaches nothing, so the question
never arises.

**A recording still has one row per attempt.** The cassette format does not move
(§5).

### 1.2 What "pure" means

Literals, list construction, reads of names already bound (including `state` and
`memory`), field accesses, arithmetic, comparison, the logical operators, and the
builtins. Anything that reaches — `ask`, `call`, `consult`, `parallel map` — is
`ING6008`.

A fallback may read; it may not reach. `else placeholder` where `placeholder` was
bound earlier is legal, and it is the form to reach for when the value is worth
naming.

*Where a read is performed.* A read the fallback needs is performed before the
attempt, not after it fails. Reads are pure and idempotent, so performing one that
turns out not to be needed changes no value — and it keeps the sequence of nodes
in the record the same whether or not the fallback was taken, which is what makes
`fallbackTaken` the only difference between the two.

### 1.3 What may not carry an `else`

| Attempt | Ruling |
|---|---|
| `ask` | may |
| a tool `call` | may |
| a sub-agent `call` | may |
| `consult` | **may not** (`ING6009`) |
| `parallel map` | **may not** (`ING6009`) |
| anything else | **may not** (`ING6009`) |
| `verify` | may not, and cannot: `verify` is a statement |

`consult` is refused although it can fail. A person was asked and did not answer;
continuing with a default is continuing without them. That is the same rule that
keeps a refused approval out of §2 of [Runtime 0.7](../runtime/v0.7.md).

`parallel map` is refused because a fallback for a whole fan-out is a handler
wrapped around a block rather than a value for one attempt. The `else` belongs on
the statement inside the body, which is where the failure is and where the other
elements' work is still worth keeping.

`else` does **not** chain. `a else b else c` is a syntax error: a fallback is pure,
so it cannot fail and cannot need a fallback of its own.

### 1.4 Inside a fan-out, which is the point

Nothing about `else` is special inside a `parallel map`, and that is what makes
the shape it was designed for work:

```
entries = parallel map incidents as incident {
  writeup = call fs.read_file("${incident.id}.md") else "no write-up was filed"
  ask<entry>("Summarise this incident.", context: writeup)
}
```

The iteration does not fail, so the fan-out does not fail, and **the collected
list keeps one entry per element**. Before 0.4 a fan-out that lost one element
spent the whole fan-out and returned nothing: iterations are drained rather than
cancelled ([Runtime 0.6 §3.4](../runtime/v0.6.md)), deliberately, so that a
failing run's cost does not depend on the schedule.

Letting a failing iteration contribute *nothing* and shorten the list was
considered and refused. `parallel map` over `T[]` with a body of type `U` yields
`U[]` with one entry per element, and `len(entries) >= len(incidents)` is exactly
the check an author writes to catch a lost element.

### 1.5 Which types a fallback can currently be written for

`else` is permitted on every attempt in §1.3. A fallback can only be *written* for
a type this language can produce purely, which is a type with a literal —
`string`, `int`, `float`, `bool` and lists of those — or a type one of those widens
into, which after §2 means `text`.

* `call fs.read_file(p) else "nothing"` — legal, for a tool returning `string` or
  `text`. **The motivating case, and §2 is what makes the `text` half of it work.**
* `ask<int>(…) else 0` — legal.
* `ask<markdown>(…) else "nothing"` — `ING3001`. `markdown` is the more specific
  type and a string does not widen into it; see §2.
* `ask<rating>(…) else rating { … }` — does not parse. There is no record
  construction in this language.
* a sub-agent `call` — legal on the attempt, and writable only where the callee's
  output is `text`. An agent's output is always an artifact content type, and
  `markdown`, `json` and `file` have no literal.

The remainder is [GAP-045](../../docs/gaps.md#gap-045), narrowed rather than closed.
**It is stated here because a specification that implied otherwise would be the
misleading kind:** [RFC-0022](../../rfcs/0022-a-failure-an-iteration-can-absorb.md)
assumed wider coverage than the type system gives, and its second example does not
parse.

### 1.6 Precedence and the other `else`

`else` binds loosest of all operators, so `call f(x) else a || b` gives the whole
right-hand side to the fallback.

It shares a keyword with the `else` of an `if` statement and there is no ambiguity:
a statement's `else` can only follow a `}`, and a `}` never continues an
expression.

## 2. Assignability: `string` widens to `text`

[Language 0.1 §4.2](v0.1.md) permitted two widenings. There are now three:

* `int` → `float`
* `markdown` → `text`
* **`string` → `text`** — new in 0.4

All three go the same way, from the more specific type to the less, and all three
are lossless. A string is text, exactly as markdown is text.

*Why it is in this document.* Without it `else` does not reach the program it was
designed for. The shipped filesystem tool reads a file as `text`, so the RFC's
motivating line — `call fs.read_file("…") else "no write-up was filed"` — was
`ING3001`. The available workaround was to declare the tool `-> string` instead,
which makes a tool's declared return type depend on whether some flow wants a
fallback. A declaration should describe the tool.

*Why it stops there.* `string` → `markdown` is **not** admitted, and the reason is
the direction rather than caution. The three rules above widen; that one would
narrow, letting an arbitrary string claim the more specific type. Admit it and
there is no ground left to refuse `text` → `markdown` — a `text` value is no less
markdown than a bare string is — and then `markdown` and `text` are one type with
two names, which is not what an artifact's content type or its file extension mean.

A program that wants a prose fallback asks for `string` and lets the step that
assembles the document produce the `markdown`. That is what the conformance case
and both trial programs do without being told to.

*Compatibility.* Purely additive: it makes programs compile that did not, and no
program that compiled behaves differently. One consequence worth naming: a
constant may now be emitted as a `text` artifact (`emit note = "nothing yet"`).
That is not a guarantee anything rested on — no check ever asserted an artifact's
bytes came from a model — and it is occasionally what an author means.

## 3. Effects

The expression's effects are the attempt's and only the attempt's. A pure fallback
declares none, which is §1.1 restated where the effect set is built.

## 4. Static bounds

A fallback contributes nothing to the lower bound on steps
(`ING5006` is computed from the attempt alone), for the reason in §1.1. An
artifact that fits its `steps` budget without an `else` fits with it.

## 5. IR and cassette impact

IR version moves to **0.4**: a node gains an optional `fallback` value. A node
without one encodes exactly as it always did, so **every artifact compiled before
0.4 is a valid 0.4 artifact.** See [Agent IR 0.4](../ir/v0.4.md).

**The cassette does not move. It is still 0.3.** A recorded failure is already a
recorded failure: `ToolExchange` has carried `error` since cassette 0.2. A model
answer that did not match its declared type is recorded as the value it was and
rejected when the run validates it, one layer further in — so a recording can hold
a model failure too, without a field for one.

What a 0.3 cassette **cannot** hold is a model call that never returned a value at
all: a provider that was unreachable, refused, or timed out. `Interaction` records
a value and has no field for an error. So `ingot test` cannot cover a provider
outage. That is [GAP-046](../../docs/gaps.md#gap-046), and it is older than this
feature — `else` only made it visible.

## 6. Diagnostics

| Situation | Diagnostic |
|---|---|
| `else` under language 0.3 or older | `ING1020`, error |
| a fallback that reaches something | `ING6008`, error |
| `else` on `consult`, `parallel map`, or anything that cannot fail | `ING6009`, error |
| a fallback whose type does not match the attempt's | `ING3001`, error |
| `a else b else c` | `ING1010`, error |

## 7. Compatibility

Purely additive. `else` is already a reserved word — it is the `if` statement's
arm — so no program that compiled under 0.3 parses differently under 0.4, and
nothing that was legal became illegal.

The gate is on the declared language version, so a file keeps its 0.3 behaviour
until its header moves.

## 8. Formatter

`<attempt> else <fallback>`, on one line, with a single space either side of the
keyword. The formatter does not break a fallback onto its own line: the value of
`else` is that it reads as part of the statement it belongs to.
