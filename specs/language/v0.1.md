# Ingot Language Specification, version 0.1

Status: **Draft**. Normative for the `0.1` language version.

This document defines the syntax and static semantics of Ingot. Where this
document and the implementation disagree, this document is authoritative and the
implementation has a bug.

Conformance tests for each rule live in `tests/` and in the unit tests of the
crate that implements the rule; a rule without a test is not considered
specified.

---

## 1. Design rules

These constrain every later decision.

1. **Static before dynamic.** Anything checkable before the agent runs is
   checked before the agent runs: types, tool signatures, prompt placeholders,
   capabilities, loop bounds and step budgets.
2. **Default-deny.** An effect is available only if the `policy` block grants
   it. An absent rule is a denial. Silence never means permission.
3. **Statically bounded.** Every loop declares a maximum. Recursion is rejected.
   A flow's shortest path is compared against its step budget at compile time.
4. **One canonical form.** A valid program has exactly one formatting and lowers
   to exactly one IR document, byte for byte.
5. **Small core, namespaced growth.** Vendor extensions arrive under namespaces;
   the core semantics stay fixed within a language version.
6. **No hidden host language.** A program's meaning never depends on a callback
   written in another language.

## 2. Lexical structure

### 2.1 Encoding and layout

Source files are UTF-8. Line endings are LF or CRLF. Layout is not significant:
newlines separate declarations by convention, not by grammar.

Identifiers match `[A-Za-z_][A-Za-z0-9_]*`. Identifiers are ASCII in 0.1;
non-ASCII identifiers are reserved for a later version.

### 2.2 Comments

```
// line comment
/// doc comment, attached to the following declaration
/* block comment, /* nestable */ */
```

Doc comments attach to the declaration that follows and are carried into the IR
as the `doc` field of an agent.

### 2.3 Literals

| Form | Example | Type |
|------|---------|------|
| Integer | `60`, `120_000` | `int` |
| Integer with binary suffix | `128k`, `2m` | `int` (× 1024, × 1048576) |
| Float | `0.2` | `float` |
| Boolean | `true`, `false` | `bool` |
| String | `"text"` | `string` |

`128k` is exactly `131072`. The suffix is only recognised when the next
character cannot continue an identifier, so `2kb` lexes as `2` followed by `kb`.

String literals are single-line. Escapes: `\n`, `\r`, `\t`, `\\`, `\"`, `\$`.

### 2.4 Interpolation

A string may contain `${path}` placeholders, where `path` is a name optionally
followed by field accesses, or `state.field`. Placeholders are resolved and
type-checked at compile time (`ING2009` when a placeholder does not resolve).
Write `\${` for a literal dollar-brace.

Placeholders may only *read* values. Calls and arbitrary expressions inside a
placeholder are rejected: a prompt must not hide work.

### 2.5 Reserved words

```
language package type tool verifier agent
model tools memory budget policy flow
requires exact mcp working ephemeral
allow deny require approval
ask call parallel map as verify emit
if else loop max while checkpoint state
true false
```

Everything else is an ordinary identifier, including effect names, policy
subjects, budget keys, currencies and model capabilities. Keeping that
vocabulary unreserved is what lets it grow without breaking existing source.

## 3. Compilation unit

```
program        := language-decl package-decl? item*
language-decl  := "language" MAJOR "." MINOR
package-decl   := "package" dotted-name
item           := type-decl | tool-decl | verifier-decl | agent-decl
```

`language` is **required** and must be the first declaration (`ING1021`). A
compiler that does not implement the declared version rejects the file
(`ING1020`) rather than guessing. A file must declare at least one agent
(`ING2013`).

Module imports are **not** part of 0.1. A compilation unit is a single file.

## 4. Types

### 4.1 Type universe

| Category | Types |
|----------|-------|
| Scalars | `string`, `int`, `float`, `bool`, `json`, `bytes` |
| Content | `text`, `markdown`, `file` |
| List | `T[]` |
| Record | declared with `type` |

Artifact content types — the `T` in `-> name<T>` — are `text`, `markdown`,
`json` and `file` (`ING3008`).

### 4.2 Assignability

Language 0.1 permits exactly two widenings, both lossless:

* `int` → `float`
* `markdown` → `text`

Nothing else converts, in either direction, and lists widen only through those
same rules. There is no implicit stringification and no `any`.

### 4.3 Records

```
type search_result {
  title: string
  url: string
  snippet: string
}
```

Fields are accessed with `.`. Records may reference each other. Records have no
methods and no defaults in 0.1.

## 5. Declarations

### 5.1 Tools

```
tool web.search(query: string) -> search_result[] !network
tool files.write(path: string, data: bytes) -> file !filesystem_write
```

A tool declaration is a *signature*: it states what the tool takes, returns and
does. It grants nothing. Declared effects come from this set:

`network`, `filesystem_read`, `filesystem_write`, `external_write`,
`secret_access`

`model_access` cannot be declared on a tool: it belongs to `ask` alone.

### 5.2 Verifiers

```
verifier CitationCheck(draft: markdown, min_sources: int)
```

A verifier is a deterministic check the runtime performs on a value. Declaring
it is what makes a `verify` statement type-checkable.

### 5.3 Agents

```
agent ResearchAgent(topic: string) -> report<markdown> {
  model   ...
  tools   ...
  memory  ...
  budget  ...
  policy  ...
  flow    ...
}
```

Every section is optional except `flow` (`ING2008`), and each may appear at most
once (`ING2011`). An agent must declare an output (`ING2015`).

The canonical section order is the one above; `ingot fmt` enforces it.

#### `model`

```
model requires {
  tool_calling
  structured_output
  context >= 128k
}
```

or a pinned reference:

```
model exact "openai/gpt-5"
```

Known capabilities: `tool_calling`, `structured_output`, `streaming`, `vision`,
`reasoning`, `parallel_tool_calls`. An unknown capability is a **warning**
(`ING4008`) and is passed through to the backend, which may reject it.

#### `tools`

```
tools {
  mcp web.search
}
```

Grants a declared tool to this agent over a transport. `mcp` is the only
transport in 0.1 (`ING2016`). Calling an ungranted tool is an error
(`ING2005`); granting a tool that is never called is a warning (`ING2012`).

#### `memory`

```
memory {
  working ephemeral {
    queries: string[]
  }
}
```

`ephemeral` is the only lifetime in 0.1 (`ING2017`). Fields are read as
`state.name` and written as `state.name = value`.

#### `budget`

```
budget {
  steps  <= 60
  tokens <= 120000
  cost   <= 5 usd
}
```

Keys: `steps`, `tokens`, `cost`. Values must be positive (`ING5002`). `cost`
requires a currency from `usd`, `eur`, `try` (`ING5005`).

One **step** is one `llm.call`, `tool.call` or `agent.call`. If the flow's
shortest path needs more steps than the budget allows, the program is rejected
(`ING5006`).

#### `policy`

```
policy {
  network allow ["arxiv.org", "github.com"]
  filesystem_write allow ["target/review"]
  external_write require approval
  secrets deny export
}
```

Subjects: `network`, `filesystem_read`, `filesystem_write`, `external_write`,
`secrets`. Each maps to one effect; `secrets` governs `secret_access`.

Actions:

| Action | Meaning |
|--------|---------|
| `allow` | permitted |
| `allow [ ... ]` | permitted, restricted to the listed values |
| `deny` | rejected at compile time (`ING4001`) |
| `require approval` | permitted after an approval checkpoint the compiler inserts (`ING4003`) |

Value lists apply to `network`, `filesystem_read` and `filesystem_write`. The
only qualifier in 0.1 is `export` on `secrets`. Values must be literal strings:
a policy that depended on a runtime value could not be checked statically.

**An absent subject is a denial** (`ING4007`). The diagnostic differs from an
explicit `deny` so the fix — stating the intent in the source — is obvious.

`model_access` is implicitly granted and takes no policy rule.

## 6. Flow

### 6.1 Statements

```
name = expression                 // binding
state.field = expression          // write to working memory
call tool.name(args)              // call for effect
verify Verifier(args)             // deterministic validation
emit output = expression          // produce the declared artifact
checkpoint "label"                // resumable boundary
if condition { ... } else { ... }
loop max N while condition { ... }
```

### 6.2 Bindings

A name is bound exactly once per agent. Rebinding and shadowing are both
rejected (`ING2002`), which makes a flow a dataflow graph and lets a reference
resolve without carrying scope information into the IR. Use `state` for values
that change.

A binding is visible from the statement after the one that introduces it, to the
end of its block. An unused binding is a warning (`ING6002`); prefix it with `_`
to keep it deliberately.

### 6.3 Expressions

| Form | Meaning |
|------|---------|
| `ask<T>(prompt, ...)` | model call returning `T` |
| `call name(args)` | tool or sub-agent call |
| `parallel map xs as x { ... }` | bounded fan-out returning a list |
| `len(x)` | length of a list or text value |
| `a == b`, `<`, `<=`, `>`, `>=`, `!=` | comparison, non-chaining |
| `a && b`, `a \|\| b`, `!a` | logic |
| `a + b`, `a - b`, `-a` | arithmetic |
| `[a, b]` | list |
| `name`, `name.field`, `state.field` | reads |

`ask` takes one positional argument — the prompt — plus optional named
arguments `context`, `system`, `temperature` and `max_tokens`. Its effect is
`model_access`.

Comparisons do not chain: `a < b < c` is a syntax error rather than a surprise.

### 6.4 `parallel map`

```
sources = parallel map queries as query {
  call web.search(query)
}
```

The source must be a list (`ING3004`). The body runs once per element, in an
unspecified order, and must end in an expression statement (`ING3005`); the
value of that statement is the element's contribution. Mapping `T[]` with a body
of type `U` yields `U[]`.

`emit`, `checkpoint` and writes to `state` are rejected inside a body
(`ING6005`): iterations are concurrent, and these would make the result depend
on scheduling.

### 6.5 Loops

`loop` requires `max` (`ING5001`). The optional `while` guard is evaluated
before each iteration. A bounded loop may run zero times, which is why it never
counts toward a guaranteed emission or a minimum step count.

### 6.6 Outputs

An agent must emit its declared output somewhere (`ING6001`), and the emitted
value's type must match the declared content type (`ING3007`).

If some path can finish without emitting, that is a warning (`ING6004`), not an
error. Emitting in both arms of an `if`/`else` satisfies the check; emitting
only inside a loop or a single arm does not.

## 7. Effects and capabilities

Effects are the observable, security-relevant things a program can do:

| Effect | Meaning |
|--------|---------|
| `network` | outbound network access |
| `filesystem_read` | reads from the workspace |
| `filesystem_write` | writes to the workspace |
| `external_write` | side effects outside the workspace |
| `secret_access` | reads a secret |
| `model_access` | calls the model; implicit on `ask`, always granted |

A call's effects are its tool's declared effects. A sub-agent call's effects are
bounded by the union of the effects of the tools that agent grants — available
before its own flow is checked, which is what lets an agent call one declared
later in the file.

Each effect is checked against the policy at the call site. Denied (`ING4001`)
and unspecified (`ING4007`) both stop the build.

## 8. Diagnostics

Codes are stable and never reused for another meaning.

| Range | Area |
|-------|------|
| `ING1xxx` | lexing and parsing |
| `ING2xxx` | names and declarations |
| `ING3xxx` | types |
| `ING4xxx` | effects, capabilities, policy |
| `ING5xxx` | budgets and static bounds |
| `ING6xxx` | lowering and IR |

`ingot explain ING4001` prints the long form.

## 9. Not in 0.1

Deliberately absent, each awaiting its own RFC:

* module imports and multi-file programs
* optional types, unions, generics, user-defined functions
* persistent memory and state migration
* streaming and incremental output
* dynamic agent creation, agent values
* transports other than MCP; WASI components; OpenAPI-derived tools
* organisation-level policy composition
* statistical evaluation suites

## 10. Grammar

```ebnf
program        = language-decl , [ package-decl ] , { item } ;
language-decl  = "language" , INT , "." , INT ;
package-decl   = "package" , dotted-name ;
dotted-name    = IDENT , { "." , IDENT } ;

item           = type-decl | tool-decl | verifier-decl | agent-decl ;

type-decl      = "type" , IDENT , field-block ;
field-block    = "{" , { field , [ "," ] } , "}" ;
field          = IDENT , ":" , type ;
type           = IDENT , { "[" , "]" } ;
params         = "(" , [ field , { "," , field } ] , ")" ;

tool-decl      = "tool" , dotted-name , params , "->" , type , { "!" , IDENT } ;
verifier-decl  = "verifier" , IDENT , params ;

agent-decl     = "agent" , IDENT , params , [ "->" , output ] , "{" , { section } , "}" ;
output         = IDENT , "<" , IDENT , ">" ;
section        = model-block | tools-block | memory-block
               | budget-block | policy-block | flow-block ;

model-block    = "model" , ( "exact" , STRING
                           | "requires" , "{" , { model-req } , "}" ) ;
model-req      = IDENT | "context" , ">=" , INT ;

tools-block    = "tools" , "{" , { IDENT , dotted-name } , "}" ;

memory-block   = "memory" , "{" , [ "working" , IDENT , [ field-block ] ] , "}" ;

budget-block   = "budget" , "{" , { IDENT , "<=" , NUMBER , [ IDENT ] } , "}" ;

policy-block   = "policy" , "{" , { policy-rule } , "}" ;
policy-rule    = IDENT , policy-action ;
policy-action  = "allow" , [ IDENT | string-list ]
               | "deny" , [ IDENT ]
               | "require" , "approval" ;
string-list    = "[" , [ STRING , { "," , STRING } ] , "]" ;

flow-block     = "flow" , block ;
block          = "{" , { statement } , "}" ;

statement      = IDENT , "=" , expression
               | "state" , "." , IDENT , "=" , expression
               | "emit" , IDENT , "=" , expression
               | "verify" , IDENT , args
               | "checkpoint" , STRING
               | "if" , expression , block , [ "else" , block ]
               | "loop" , [ "max" , INT ] , [ "while" , expression ] , block
               | expression ;

expression     = or-expr ;
or-expr        = and-expr , { "||" , and-expr } ;
and-expr       = cmp-expr , { "&&" , cmp-expr } ;
cmp-expr       = add-expr , [ ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) , add-expr ] ;
add-expr       = unary , { ( "+" | "-" ) , unary } ;
unary          = [ "!" | "-" ] , primary ;
primary        = STRING | NUMBER | "true" | "false"
               | "[" , [ expression , { "," , expression } ] , "]"
               | "ask" , "<" , type , ">" , args
               | "call" , dotted-name , args
               | "parallel" , "map" , expression , "as" , IDENT , block
               | IDENT , "(" , [ expression , { "," , expression } ] , ")"
               | "state" , { "." , IDENT }
               | IDENT , { "." , IDENT }
               | "(" , expression , ")" ;
args           = "(" , [ arg , { "," , arg } ] , ")" ;
arg            = [ IDENT , ":" ] , expression ;
```
