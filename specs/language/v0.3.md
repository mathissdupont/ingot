# Ingot Language Specification, version 0.3

Status: **Draft, implemented**. Normative for the `0.3` language version where
this document defines behaviour. Language 0.3 inherits Language 0.2 except where
this document explicitly says otherwise.

Implemented in this draft:

* `consult`, a question put to a person, whose answer the flow reads.
* the `human` effect and its policy subject.

Designed in [RFC-0020](../../rfcs/0020-a-person-in-the-loop.md).

---

## 1. `consult`

A new expression, beside `ask` and `call`:

```
framing = consult("Which framing should the report take?")
```

The common form limits what may come back:

```
framing = consult(
  "Which framing should the report take?",
  choices: ["technical", "executive", "narrative"]
)
```

And a question that needs the run's own work in front of it says so, with the
named argument `ask` already uses:

```
approach = consult(
  "The draft argues two things and they do not sit together. Which do we keep?",
  context: [draft],
  choices: ["the cost argument", "the risk argument"]
)
```

`consult` takes one positional argument — the question — plus the optional named
arguments `context` and `choices`. Its effect is `human`.

### 1.1 The type of an answer

**`consult` has no type parameter, and its value is always `string`.** A person
types text or picks from a list, so `string` is the only answer there is — and a
type parameter with exactly one legal value is not a type parameter.

There is deliberately no `consult<Report>`. A model can be schema-constrained
into a struct; a person confronted with one is being asked to type JSON, which
is the failure [RFC-0016](../../rfcs/0016-the-canvas.md) named when it decided
the canvas may widen a policy: a surface that leaves somebody stuck sends them
to paste something they do not understand. A program that wants structure asks a
model to build it from what the person said.

*The better answer, deferred.* With literal types in the union machinery from
[RFC-0009](../../rfcs/0009-language-v0.2-optionals-and-unions.md), the choice
form would yield `"technical" | "executive" | "narrative"` and a match over it
would be exhaustively checked. That narrows a type later without changing this
syntax.

### 1.2 `choices`

`choices` is a list of **string literals** (`ING3015`), and it may not be empty.

Literals rather than values, and it is not fussiness. The possible answers being
in the source before anybody is asked is what lets a reviewer see everything a
recording could contain — so the choice form cannot leak something that was not
already committed. A computed list would give that up while looking identical.

> **Amended by [GAP-047](../../docs/gaps.md#gap-047).** The reason in the
> paragraph above does not hold. A `consult`'s *question* is an ordinary
> expression and may be a model's output, so nobody sees the interaction before
> it happens and a literal answer menu does not make it reviewable. What holds is
> the reason in the paragraph below: `choices` is a **constraint the runtime
> enforces**, not data in the source. The rule this section states is unchanged.

When `choices` is present the runtime **guarantees the value is one of them**. A
channel that returns anything else fails the run rather than binding it: the
program limited what may come back, so the runtime holds the limit. A channel is
not a trusted source because a person is behind it.

### 1.3 `context`

`context` works as it does on `ask`, and it is not decoration.

A person's answer can depend on something they saw earlier. If that dependency
is real and a recording's digest does not cover it, two runs whose question text
is identical can deserve different answers, and a replay would serve the first
into the second without noticing. So the rule `ask` already keeps applies:
**whatever determined the answer is an argument, and every argument is in the
digest.**

### 1.4 Where a `consult` may not appear

Two places, and both already had the rule and the reason.

**Inside `parallel map` (`ING6005`)**, joining `emit`, `checkpoint` and state
writes. Those are refused because iterations run concurrently. Questions to a
person are worse than order-dependent: the order is *observable to the person*,
who would see several arrive at once with no way to know which branch each
belongs to.

**Inside a verifier or helper body (`ING2019`).** [Language 0.2
§10.1](v0.2.md) gives the reason unchanged: *a verifier's outcome has to be
reproducible from the run record alone, and a body that could reach outside the
run would not be.* A question reaches outside the run — that is the point of it.
A check that genuinely needs a person is a `consult` in the flow followed by a
`verify` of what came back.

### 1.5 Static bounds

A `consult` consumes one step, like a model or tool call. Inside `loop max N` it
can ask N questions, bounded by the loop bound the language already requires, so
nothing new bounds it and nothing new needs to.

## 2. The `human` effect

`human` joins the effect table in [Language 0.1 §7](v0.1.md):

| Effect | Meaning |
|--------|---------|
| `human` | puts a question to a person and waits for the answer |

It is a policy subject of the same name, and default-deny applies unchanged: a
program calling `consult` without `human` granted is `ING4007`, before it runs.

This is what the effect is for. **"Can this artifact run unattended?" becomes a
question you answer by reading its policy**, rather than by starting it and
finding out. CI denies `human`; an artifact that needs a person fails at the
gate naming the question instead of waiting on a pipe. A scheduler can refuse to
enqueue what it cannot answer.

### 2.1 `human` takes `allow` and `deny`, and not `require approval`

`human require approval` is `ING4011`. An approval gate in front of a question is
a question in front of a question, and the person answering the first is the
person who would answer the second.

`human` takes no value list: it names no resource, and it declares no reach
(`Effect::takes_reach` is false), for the reason `external_write` and
`secret_access` declare none.

### 2.2 A sub-agent may ask, and its caller must have said so

A sub-agent call's effects are bounded by the union of the effects of the tools
that agent grants ([Language 0.1 §7](v0.1.md)). That is a rule about tools, and
`human` is not a tool, so it is stated rather than inherited: **`human`
propagates like every other effect, and a caller whose policy does not grant it
cannot call an agent that consults.**

The alternative would let an agent acquire a person's attention by delegation,
which is the shape of every capability escape this project refuses. It does not
become acceptable because the thing reached is a person rather than a socket.

## 3. IR impact

A new node kind, `consult`, carrying the question as `prompt`, `choices` and
`context` as `args`, `responseType` of `string`, and `human` in `effects`.

IR version moves to **0.3**. A new node kind is a document an 0.2 reader must not
accept, and refusing beats mis-reading.

A backend that cannot reach a person must refuse the artifact at build time
rather than accept it and fail at the node. An artifact that builds and cannot
run is the failure the effect system exists to prevent, and a backend gets no
exemption from it.

## 4. Diagnostics

| Situation | Diagnostic |
|---|---|
| `consult` under language 0.2 or older | `ING1020`, error |
| `consult` with no question | `ING3011`, error |
| a question that is not a `string` | `ING3001`, error |
| more than one positional argument | `ING3002`, error |
| `choices` that are not string literals, or empty | `ING3015`, error |
| an unknown named argument | `ING3003`, error |
| `consult` without `human` granted | `ING4007`, error |
| `human` denied | `ING4001`, error |
| `human require approval` | `ING4011`, error |
| `consult` inside `parallel map` | `ING6005`, error |
| `consult` in a verifier or helper body | `ING2019`, error |

## 5. Compatibility

**`consult` is a new reserved word.** A program that binds a name `consult`
compiles under 0.1 and 0.2 and does not compile under 0.3. The keyword is gated
on the declared language version, so an existing file keeps working until its
header moves.

A contextual keyword would have made the grammar depend on what is in scope,
which costs more than the break does.

Everything else is additive: `human` is a new effect name, and an effect name has
always been an ordinary identifier in every position but a policy subject.

## 6. Formatter

`consult` prints as a call with its arguments, wrapping the same way `ask` does.
There is no type parameter to print.
