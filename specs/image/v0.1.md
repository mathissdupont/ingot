# Ingot Package Specification, version 0.1

Status: **Draft, implemented**. Normative for
`"artifactType": "application/vnd.ingot.package.v1+json"`.

An Ingot package distributes checked Agent IR and the metadata that identifies
it. It is an [OCI image layout][layout] holding one artifact manifest, so it
moves through OCI registries with existing tools and needs no Ingot-specific
transport.

The reasoning behind every rule here is in
[RFC-0012](../../rfcs/0012-the-ingot-package.md). Where this document and the
implementation disagree, this document is authoritative.

[layout]: https://github.com/opencontainers/image-spec/blob/main/image-layout.md

## 1. Layout

A package is a directory:

```text
<dir>/
  oci-layout
  index.json
  blobs/sha256/<hex>
```

`oci-layout` must be exactly:

```json
{
  "imageLayoutVersion": "1.0.0"
}
```

`index.json` must be an `application/vnd.oci.image.index.v1+json` document whose
`manifests` array holds exactly one descriptor, referring to the package
manifest. A package describes one project; an index with several entries is not
this format.

Every blob is stored at `blobs/sha256/<hex>`, where `<hex>` is the lowercase hex
`sha256` of the blob's own bytes. A blob that is referenced must be present, and
a blob that is present must be referenced.

## 2. Media types

| Media type | Content |
|------------|---------|
| `application/vnd.ingot.package.v1+json` | The `artifactType` of the manifest. Not a blob. |
| `application/vnd.ingot.package.config.v1+json` | The config blob (§4). |
| `application/vnd.ingot.agent-ir.v1+json` | One Agent IR document, verbatim. |
| `application/vnd.ingot.lock.v1+json` | The lockfile (§5). |
| `application/vnd.ingot.portability.v1+json` | One target's portability report. |

These media types version the **envelope**, not the document. An Agent IR blob
states its own `irVersion`; the media type says only that the blob is an Agent IR
document. A consumer must read the document's own version field and must not
infer it from the media type.

## 3. The manifest

The manifest is an `application/vnd.oci.image.manifest.v1+json` document with
`"schemaVersion": 2` and
`"artifactType": "application/vnd.ingot.package.v1+json"`.

`config` must be a descriptor for the config blob.

`layers` must contain:

- one `application/vnd.ingot.agent-ir.v1+json` descriptor per agent in the
  compilation, and
- exactly one `application/vnd.ingot.lock.v1+json` descriptor,

and may contain any number of `application/vnd.ingot.portability.v1+json`
descriptors, at most one per target.

Every layer descriptor must carry an `org.opencontainers.image.title`
annotation, which must be a **file name**: no directory separators, no `..`, and
no absolute path. An Agent IR descriptor must also carry `dev.ingot.agent`, the
fully qualified agent name.

Layers must be sorted by their `org.opencontainers.image.title`, ascending, byte
order.

The manifest must carry `org.opencontainers.image.title` (the project name) and
`org.opencontainers.image.version` (the project version) in its own
`annotations`.

The manifest must **not** carry `org.opencontainers.image.created` (§6).

The **package digest** is `sha256` of the manifest bytes.

## 4. The config

```json
{
  "agents": [
    {
      "agent": "heptapus.examples.research.ResearchAgent",
      "digest": "sha256:…",
      "title": "ResearchAgent.ir.json"
    }
  ],
  "configVersion": "1",
  "generator": "ingot 0.3.0",
  "irVersion": "0.2",
  "language": "0.2",
  "project": { "name": "research-agent", "version": "0.1.0" }
}
```

| Field | Meaning |
|-------|---------|
| `configVersion` | Version of this config shape. `"1"` for this specification. |
| `generator` | The producing toolchain and its version. |
| `language` | The language version the sources declared. |
| `irVersion` | The `irVersion` every Agent IR blob in this package carries. |
| `project` | Declared project identity, from the manifest. |
| `agents` | Every packaged agent, its blob digest and its layer title. |

`agents` must be sorted by `agent`. Every entry must correspond to a layer.

A package whose agents do not all carry the same `irVersion` is invalid: the
package states one, and a mixed package could not.

## 5. The lockfile

The lockfile records the **identity** of what a package was built from and what
it expects at run time. It is written both into the project, where it can be
committed and reviewed, and into the package, so a received artifact is
self-describing. Both copies must be byte-identical.

```json
{
  "agents": [
    { "agent": "heptapus.examples.research.ResearchAgent", "digest": "sha256:…" }
  ],
  "image": "ingot/run:0.3.0",
  "ingot": "0.3.0",
  "irVersion": "0.2",
  "language": "0.2",
  "lockVersion": "1",
  "modelProviders": [
    {
      "apiKeyEnv": "OPENAI_API_KEY",
      "baseUrl": "https://api.openai.com/v1/chat/completions",
      "name": "openai"
    }
  ],
  "project": { "name": "research-agent", "version": "0.1.0" },
  "sources": [{ "digest": "sha256:…", "path": "main.ing" }],
  "toolServers": [
    {
      "args": ["--root", "data", "--allow-write"],
      "command": "ingot-mcp-fs",
      "image": "ingot/mcp-fs:0.2",
      "name": "workspace",
      "passEnv": ["GITHUB_TOKEN"]
    }
  ]
}
```

| Field | Meaning |
|-------|---------|
| `lockVersion` | Version of this lockfile shape. `"1"` for this specification. |
| `ingot` | The compiler version that produced the package. |
| `sources` | Every compilation unit, by project-relative path and content digest. |
| `agents` | Every agent, by name and Agent IR blob digest. |
| `toolServers` | Declared MCP servers, by name, command, arguments, forwarded variable **names** and image. |
| `modelProviders` | Declared model services, by name, endpoint and the **name** of the variable holding their key. |
| `image` | The image a contained run expects, when the project declares one. |

`sources`, `agents`, `toolServers` and `modelProviders` must be sorted by their
first field, and omitted entirely when empty.

A source `path` must be project-relative and slash-normalized, with no `..`
component and no drive letter, under the same rule Agent IR 0.2 applies to
`sourceSpan.source`.

**No field in this document may hold an environment value.** `passEnv` and
`apiKeyEnv` hold variable names. This is the same rule
[the manifest](../../crates/ingot-cli/src/manifest.rs) already enforces for
`[[mcp.server]]`, and for the same reason: a lockfile is committed.

## 6. Reproducibility

The same source, the same project manifest and the same compiler must produce
the same package digest on every platform.

A producer must:

- write every JSON document it generates — the config, the lockfile, the
  portability report, the manifest, the index and `oci-layout` — in the canonical
  encoding of [ADR-0004](../../docs/adr/0004-canonical-ir-encoding.md): sorted
  object keys, two-space indentation, exactly one trailing newline;
- copy each Agent IR blob **verbatim** from what the compiler produced, without
  re-encoding it;
- sort layers by title;
- omit `org.opencontainers.image.created` and every other timestamp;
- store no path from the build machine, in any field;
- compress nothing.

A producer must not include any value that varies between two builds of the same
inputs. Where a producer cannot satisfy that, it must fail rather than emit a
package whose digest is a serial number.

## 7. What a package must never contain

- A credential value, of any kind, in any blob.
- A cassette, or any other recording of model output.
- Source text. Source identity belongs in `sources[].digest`; the text does not
  travel.
- An absolute path, a home directory, a user name or a host name.
- A timestamp.
- Any editor, session or conversation state.

## 8. The secret scan

Before a package or a build is written, a producer must scan the project's
source files, the compiled Agent IR bytes and every cassette in the project for
credential-shaped **values**, and must refuse when it finds one.

The following shapes are normative minimums:

| Shape | Recognised as |
|-------|---------------|
| `sk-`, `sk_live_`, `ghp_`, `github_pat_`, `xoxb-`, `AIza` followed by ≥16 opaque characters | a vendor-prefixed API key |
| `Bearer ` followed by ≥16 opaque characters | a bearer token |
| `api_key`, `apikey`, `api-key`, `secret`, `password`, `passwd` or `token`, then `=` or `:`, then ≥16 opaque characters | an assigned credential value |

An *opaque character* is ASCII alphanumeric or one of `- _ + / =`. The run ends
at the first character outside that set, so ordinary prose after a marker is not
a finding.

A refusal must name the file, the line and the shape. It **must not** reproduce
the value: a report that quotes a credential has copied it into a terminal and a
CI log.

The scan is a check on the author, not a security boundary. It recognises what it
recognises. The commitment in [SECURITY.md](../../SECURITY.md) is that the
toolchain provides no *path* for a secret to enter an artifact; this scan does
not replace that property and must not be described as if it did.

## 9. Image references and digest pinning

An image reference in `[run] image`, in `--image` or in a lockfile may be
digest-pinned:

```text
ingot/run@sha256:<64 hex characters>
```

Before a contained run starts with a pinned reference, a runner must compare the
pin with the digest of the image present locally, and must refuse when they
differ, naming both. A reference without a digest behaves as it did before this
specification: it identifies an image by tag and is verified only by presence.

A runner must not acquire an image automatically. Automatic acquisition requires
all three of a signature over the manifest digest, a documented trust root, and a
refusal path for an unsigned or unverifiable image. Until those exist, a missing
image is an error that names how to build it, and never a download and never a
host-run fallback.

## 10. Verification

A verifier given a package directory and a project must report, without changing
either:

- any blob whose content does not hash to the digest naming it;
- any descriptor whose digest or size does not match its blob;
- any source whose current content digest differs from the lockfile's;
- any agent whose freshly compiled Agent IR differs from the packaged blob.

Each difference is reported by name. A verifier must not repair anything: what it
is for is telling you that the artifact and the working tree have diverged, and
which way.

## 11. Versioning

`lockVersion`, `configVersion` and the media-type versions move independently of
the language version, the Agent IR version and the CLI version, under the rules
in [GOVERNANCE.md](../../GOVERNANCE.md).

A consumer that does not recognise a `lockVersion` or `configVersion` must refuse
the package rather than read the fields it happens to understand.
