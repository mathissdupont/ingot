# Runtime Specification, version 0.1

Status: **Draft**. Normative for backends consuming Agent IR `0.1`.

This document says what it means to *execute* an Agent IR document. Where it and
[the IR specification](../ir/v0.1.md) overlap, the IR specification defines the
data and this one defines the behaviour.

The reference implementation is `ingot-runtime`. It is the oracle: where this
prose is ambiguous, the reference interpreter's behaviour is the tiebreak, and
the ambiguity is a bug in this document.

---

## 1. What a backend is

A backend takes an Agent IR document and executes it, or refuses. It supplies
two things the interpreter does not:

```rust
trait ModelProvider {
    fn name(&self) -> &str;
    fn complete(&mut self, request: &CompletionRequest) -> Result<CompletionResponse, ProviderError>;
}

trait ToolHost {
    fn name(&self) -> &str;
    fn provides(&self, tool: &str) -> bool;
    fn call(&mut self, invocation: &ToolInvocation) -> Result<Value, ToolError>;
}
```

Everything vendor-specific lives behind those. The interpreter never learns which
provider answered.

## 2. Refuse rather than skip

This is the rule the rest of the specification depends on. A backend **must**
stop, with an error naming what it could not do, when it encounters:

* an `irVersion` whose major component it does not implement
* an unknown `kind` on a node
* an unknown `kind` on a value
* a policy decision it cannot enforce
* an `approval` node it cannot pause for
* a `value` of kind `unknown`

Skipping any of these produces an agent that appears to work while doing less
than the artifact says. A restriction that is silently dropped is worse than a
build that fails.

## 3. Startup

1. **Check the version.** Reject an unimplemented major (§2).
2. **Bind inputs.** Every entry in `inputs` must be supplied and must match its
   declared type. A missing input, a wrongly typed input, or a supplied name the
   artifact does not declare, is an error **before** any node runs — nothing is
   sent to a provider until the inputs are known good.
3. **Fix the step ceiling.** The effective limit is `budget.steps` when set,
   further reduced by any operator-supplied cap.

## 4. Executing a region

A region is a chain of nodes reached by following `next` from an entry id, until
`next` is `null`. `entry` names the top-level region; `then`, `else` and `body`
name nested ones.

Nested regions terminate with `next: null`; control then returns to the node
after the container. Node ids record creation order, not execution order, and a
region's nodes may have lower ids than their container.

## 5. Node semantics

| Kind | Behaviour |
|------|-----------|
| `llm.call` | Charge one step. Render `prompt`, evaluate `args`, request `responseType` (§6). Validate the answer against the declared type. Bind the result. |
| `tool.call` | Check effects against policy (§7). Charge one step. Refuse if no host provides the tool. Invoke, validate the result against the tool's declared result type, bind it. |
| `agent.call` | Check effects, charge one step, then run the named agent as a **fresh run** against its own artifact — its own budget, its own policy. Bind its first output. |
| `branch` | Evaluate `condition`; run `then` or `else`. A non-boolean condition is an error. |
| `parallel` | Evaluate `source` (must be a list). Run `body` once per element with the element bound to `binder`. The iteration's value is the result of the **last node in `body`**. Bind the list of those values. |
| `loop` | Run `body` at most `maxIterations` times, checking `guard` before each iteration. The bound is enforced even when the guard never falsifies. |
| `approval` | Ask the operator. A denial ends the run. |
| `verify` | Evaluate the arguments. IR 0.1 carries no verifier implementation, so a backend may treat this as a no-op; it **must not** report a check as passed if it can perform it and it failed. The reference interpreter reports `passed: true` regardless, which is legal and wrong: [GAP-002](../../docs/gaps.md#gap-002). |
| `state.read` | Read a working-memory field. Reading before writing is an error, not `null`. |
| `state.write` | Evaluate and store, after validating against the declared field type. |
| `artifact.emit` | Evaluate and record the output, after validating against the declared content type. |
| `checkpoint` | Emit an event. Resumption is not defined in 0.1. |

At the end of the run, every entry in `outputs` must have been emitted.

### 5.1 `parallel` may be executed sequentially

The compiler guarantees a `parallel` body contains no state write, no emission
and no checkpoint, so iterations cannot observe one another. Sequential
execution therefore produces the same result as concurrent execution.

The node is called `parallel` because it marks an opportunity for concurrency,
not an obligation. Conformance asserts the **result**, never the schedule.

### 5.2 A tool host is supplied by the operator

`tool.call` names a tool the artifact declares. The artifact does not say where
that tool lives, and a backend must not infer it: which server provides
`web.search` is deployment configuration, and it is what lets one artifact run
in more than one place.

A backend therefore takes a **tool host** from whoever invoked it, and the host
either serves a declared tool or does not. There is no third answer:

* the effects check in §7 happens **before** the host is consulted, so a call the
  policy forbids never reaches a server;
* a tool no host serves ends the run, naming the tool. Skipping the node and
  continuing is a conformance failure — the flow after it was type-checked
  against a value that would not exist.

The result a host returns is validated against the tool's declared result type
exactly as a model response is (§6). A host may choose which part of a
protocol-level reply to believe; it may not widen a type.

The binding to the Model Context Protocol is specified separately, in
[`specs/tools/mcp-v0.1.md`](../tools/mcp-v0.1.md). It is one host
implementation, not part of this specification: a backend may host tools any way
it likes and still conform.

## 6. Requesting a typed response

`responseType` determines how the request is made:

| Declared type | Treatment |
|---------------|-----------|
| `text`, `markdown` | Plain completion. The response text is the value. |
| `json` | Plain completion, parsed as JSON. |
| `string`, `int`, `float`, `bool`, `T[]`, a record | Constrained to a JSON Schema derived from the type. |
| `bytes`, `file` | Not requestable. A model cannot produce binary content; use a tool. |

Schemas derived from non-object types are wrapped as
`{"type": "object", "properties": {"value": <schema>}, "required": ["value"],
"additionalProperties": false}` and unwrapped from the response, because
provider structured-output implementations generally require an object at the
schema root.

Prose types are deliberately **not** constrained: asking for markdown and
receiving JSON-escaped markdown is worse than not constraining at all.

A response that does not validate against the declared type is an error. That is
the entire value of having declared it.

### 6.1 Values of `file` and `bytes`

Both types exist so that binary content can move **between tools** without
passing through the agent, the event stream or a cassette. Their JSON forms
reflect that.

A `file` is a handle:

```json
{ "path": "out/summary.md" }
```

`path` is required and must be a string. A producer may add further fields — a
media type, a size — and a consumer must ignore ones it does not know. The
content is deliberately absent.

A `bytes` value is a base64-encoded string, because the IR, events and cassettes
are all JSON.

Neither can be requested from a model (§6). Both may be produced by a tool and
passed to another, and neither may be interpolated into a prompt.

## 7. Enforcing policy

Before any effect, for each effect in the node's `effects`:

* `model_access` is implicitly granted and needs no rule.
* Otherwise look up the governing subject in the artifact's `policy` object.
  `secret_access` is governed by `secrets`; every other effect is governed by
  the subject of the same name.

| Found | Behaviour |
|-------|-----------|
| `allow` | proceed |
| `requireApproval` | the compiler has already inserted an `approval` node ahead of this call; proceed |
| `deny` | error, naming the effect and the explicit denial |
| nothing | error, naming the effect and stating that an absent rule is a denial |

**A backend must perform this check itself.** The compiler already did, but the
person running an artifact is frequently not the person who built it, and an
artifact that arrived over a registry is exactly the case where "the compiler
checked" is not an argument.

A rule's `values` — the hosts in `network allow [...]`, the paths in
`filesystem_read allow [...]` — are not enforced by the effect check, which only
answers yes or no. Paths are relative to the **workspace**, a root the operator
binds at run time ([Language 0.1 §7.1](../language/v0.1.md)).

A backend enforces values by bounding what the artifact runs inside, or it does
not enforce them at all. It must never report that it did when it did not: a
backend that can honour only part of a rule says which part.

The reference toolchain derives a boundary for tool servers from these values —
`ingot sandbox` prints it, [RFC-0004](../../rfcs/0004-ingot-containers.md)
specifies it — and reports a host allowlist as unenforceable, because bounding
egress to named hosts needs a proxy. Without that boundary, values are advisory:
[GAP-001](../../docs/gaps.md#gap-001).

## 8. Budgets

* **Steps.** `llm.call`, `tool.call` and `agent.call` each cost one. Exceeding
  `budget.steps` ends the run.
* **Tokens.** Accumulate reported usage across the run, including sub-agents.
  Exceeding `budget.tokens` ends the run.
* **Cost.** `budget.cost` is advisory in 0.1: a backend that can price a request
  should enforce it; one that cannot must not pretend to.

A backend may impose stricter limits than the artifact. It must never impose
looser ones.

## 9. Events

Execution emits a normalised event stream. Events carry **no timestamps and no
durations**: replaying the same recorded exchange must produce the same event
sequence byte for byte, which is what makes an event stream assertable rather
than merely inspectable.

Event kinds: `runStarted`, `nodeStarted`, `modelCall`, `toolCall`, `agentCall`,
`approvalRequested`, `approvalDecided`, `stateWritten`, `verified`,
`checkpoint`, `branchTaken`, `loopIteration`, `mapIteration`, `emitted`,
`runFinished`, `runFailed`.

## 10. Cassettes

A cassette records the model exchanges of one run so it can be replayed with no
key and no network.

```json
{
  "cassetteVersion": "0.1",
  "agent": "heptapus.examples.summarizer.DocumentSummarizer",
  "inputs": { "audience": "engineering leads", "document": "…" },
  "interactions": [
    {
      "index": 0,
      "node": "n0",
      "requestDigest": "33fc93e3…",
      "responseType": "markdown",
      "value": "# …",
      "usage": { "inputTokens": 480, "outputTokens": 210 },
      "model": "claude-opus-5"
    }
  ]
}
```

The inputs live in the cassette so it is self-contained — there is no way to
pair a recording with the wrong inputs and get a confusing digest mismatch
instead of a clear result.

Replay matches interactions in order and verifies `requestDigest`, which covers
the node, the system prompt, the rendered prompt, the context values and the
response type. A changed prompt therefore fails loudly rather than silently
reusing a stale answer.

**Cassettes are test fixtures and are reviewed like any other checked-in data.**
A recording made against real inputs contains whatever those inputs contained.

A cassette records **model exchanges only**. Tool results are not recorded, so
replay does not stand in for a tool host: an agent that calls a tool during
replay still needs one. A backend must not silently succeed a tool call because
it is replaying.

## 11. Secrets

Secrets reach a provider from the environment. They are never read from the IR,
never written to a cassette, and never included in an event.

The same rule extends to tool hosts. A host that starts a process must not hand
it the invoking environment wholesale; what it forwards must be named
explicitly, and the names — not the values — are what configuration carries.

## 12. Not in 0.1

Streaming responses, concurrent `parallel` execution, tool transports other than
a local subprocess, recorded tool results, checkpoint resumption, verifier
implementations, cost enforcement, and distributed execution. Each needs its own
RFC.

## 13. Conformance

A backend claiming conformance with Runtime 0.1 must:

1. refuse everything in §2 rather than skipping it;
2. enforce §7 from the artifact's own `policy` object;
3. enforce the step and token budgets in §8;
4. honour `maxIterations` even against a guard that never falsifies;
5. validate typed responses per §6, and tool results per §5.2, failing rather
   than coercing;
6. end the run when no host serves a declared tool, rather than skipping the
   node;
7. produce the same outputs as the reference interpreter for the conformance
   fixtures, given the same cassette.

Item 6 is about outputs, not schedules or event ordering across regions.
