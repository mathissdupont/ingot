# Runtime Specification, version 0.5

Status: **Draft, implemented**. Normative for the reference interpreter and for
every backend that executes Agent IR.

Runtime 0.5 is [Runtime 0.4](./v0.4.md) plus state that outlives a run:

1. **persistent memory** — an agent's `persistent` fields, seeded before the
   first node and handed back when the run ends;
2. **resumption** — a run may stop at a `resumable` checkpoint and continue
   later, producing exactly the events one uninterrupted run would.

Execution semantics, budgets, policy enforcement, cassettes, artifacts and every
other event are inherited from 0.4, 0.3, 0.2 and 0.1 unchanged.

Design reasoning is in
[RFC-0018](../../rfcs/0018-state-that-outlives-a-run.md).

## 1. What a backend is handed, and what it hands back

Both features work the same way, and the shape is deliberate: **a backend that
executes IR does not touch the filesystem for either of them.**

A caller supplies the persistent values a run starts from, and the run reports
the values it ended with. Where those values were read from and where they are
written is the caller's business — a file, a database row, a test fixture. The
same is true of a resumption snapshot.

A backend that opened a store itself would have to decide a path, a format and a
locking rule on behalf of every embedder, and none of those are execution
semantics.

## 2. Resumption

### 2.1 Where a run may stop

Only at a `checkpoint` node whose `resumable` is true
([Agent IR 0.2 §7.3](../ir/v0.2.md)) — the compiler sets it for a checkpoint at
the top level of a flow and for no other.

A backend that supports stopping:

* **must** stop when asked to stop at a `resumable` checkpoint with the given
  label, after emitting that checkpoint's own event;
* **must not** stop at a checkpoint whose `resumable` is absent or false;
* **must** refuse, before the run starts, a request to stop at a label that
  either does not exist or names a non-resumable checkpoint. Running to
  completion without stopping is a conformance failure: a caller that asked to
  stop and got a finished run cannot tell that from a run with no checkpoint.

A backend that does not support stopping at all is conforming. It reports so in
its portability report and refuses the request rather than ignoring it.

### 2.2 What a stopped run reports

```json
{"event":"runStopped","node":"n7","label":"sources-collected"}
```

`runStopped` replaces `runFinished` and is the **last** event. It is the only
thing that suppresses the rule in
[Runtime 0.1 §5](./v0.1.md) that every declared output must have been emitted: a
stopped run has not reached them yet, and a reader can see in the record that
the check was suppressed rather than having to infer it.

A run that neither finished, failed nor stopped is an interrupted process, and
is reported as one — not as a stop.

### 2.3 What a resumption carries

Everything the interrupted run held that the rest of it needs: the inputs, every
binding in scope, working memory, the outputs produced so far, and the counters
— steps, usage, spend.

The counters carry forward because a budget bounds a run and a run that stopped
and continued is one run. Allowing a stop to reset them would make stopping a
way to spend more than the artifact permits.

Persistent memory is **not** carried. It belongs to the agent rather than to the
interrupted run, and both halves read and write it through §3 as normal.

### 2.4 An artifact that changed is refused

A resumption identifies the artifact it belongs to by the SHA-256 of that
artifact's canonical JSON.

If it differs, the run **must** refuse, and there is no override. Continuing
against a modified program produces a result that is not what either program
would have produced, and no reader of the record could tell which parts came
from which. This is the position [Runtime 0.1 §10](./v0.1.md) already takes on a
cassette recorded for a different request.

### 2.5 The property

Let `E(r)` be the events of run `r` with `runStarted`, `runFinished`,
`runFailed` and `runStopped` removed. For an artifact, inputs and cassette
producing an uninterrupted run `U`, and a stop at any resumable checkpoint
producing `A` then `B`:

```
E(A) ++ E(B) == E(U)
```

Byte for byte, since events carry no clock. This is what makes resumption more
than a plausible story, and it is what a conformance case for it asserts.

## 3. Persistent memory

### 3.1 Seeding

Before the first node runs, a backend builds the run's persistent memory from
the artifact's `persistent` map ([Agent IR 0.2 §7.1](../ir/v0.2.md)) and the
values the caller supplied:

* a field the caller supplied takes the supplied value;
* a field the caller did not supply takes the artifact's `initial`;
* every value is validated against the field's declared type, exactly as an
  input is.

A run with no supplied values is therefore a correct first run, not a missing
one. This is what the required initial value in
[Language 0.2 §11.3](../language/v0.2.md) buys.

### 3.2 Two failures, both before anything runs

| Condition | Outcome |
|---|---|
| A supplied value does not match its declared type | The run **must** fail, naming the field. |
| A supplied field the artifact does not declare | The run **must** fail, naming the field and listing what is declared. |

Both are checked **before** `runStarted` is emitted. A store that does not fit
the artifact is not a reason to spend a token finding out.

Dropping an undeclared field silently is specifically forbidden: it is what an
older version of the agent was keeping, and losing it without a word is the
failure mode this rule exists to prevent.

### 3.3 Reading and writing

`state.read` and `state.write` with `scope: "memory"` address persistent memory;
without it, working memory. Nothing else differs:

* a persistent write validates against the declared type like an ephemeral one;
* a persistent write emits the same `stateWritten` event. Which store a field
  lives in is a property of the artifact, not of the run, and a reader who wants
  to know looks it up there;
* a persistent read can never find a field missing, because §3.1 seeded it.

### 3.4 What a run reports

The full contents of persistent memory as the run left it, including fields it
never wrote. A caller writes that back wholesale; a partial report would make
the caller merge, and merging is where a store loses data.

A run that **failed** reports nothing to write back. A partial store from a run
that did not complete is worse than the store the run started from, because
nothing in it says which half of the agent's reasoning it reflects.

### 3.5 A sub-agent has its own

An `agent.call` is a fresh run against the callee's own artifact
([Runtime 0.1 §5](./v0.1.md)), and it gets no persistent memory from its caller.
An agent that should keep memory is run as an agent.

## 4. Conformance

A conformance request carries an artifact, a cassette and inputs, and never a
store — so every case starts from the declared initial values and §3.1 is what
the `memory-initial` case pins.

Cross-run persistence and resumption are properties of a *sequence* of runs,
which the request shape cannot express. They are tested outside the suite. A
later contract revision may add them; this one does not pretend to.
