# Agent IR Specification, version 0.1

Status: **Draft**. Normative for `"irVersion": "0.1"`.

The Agent IR is the contract between the Ingot front end and every backend. It
is not written by hand and not intended as a configuration format: it is what a
backend reads to produce a runtime configuration, and what a portability report
is computed against.

The machine-readable schema is [`agent-ir.schema.json`](./agent-ir.schema.json).

---

## 1. Guarantees

1. **Canonical encoding.** Two-space indentation, object keys sorted, one
   trailing newline. The same source compiled by the same compiler produces
   byte-identical output. This is what makes a reproducible artifact digest
   possible.
2. **Flat control flow.** All nodes live in one `nodes` array. Regions — branch
   arms, loop and map bodies — are referenced by the id of their first node and
   terminate with `next: null`. A backend can walk the graph iteratively.
3. **Everything explicit.** Effects, policy decisions, budgets, approval
   checkpoints and state access are data in the document, never conventions a
   backend has to reconstruct.
4. **No source dependency.** A backend never needs the `.ing` file. Spans and
   syntax are deliberately absent.

## 2. Versioning

`irVersion` is the schema version; `language` records the language version of
the source. Adding an optional field is a minor change; changing the meaning of
an existing field, or adding a required one, is a major change.

A backend **must** reject an `irVersion` whose major component it does not
implement, rather than ignoring fields it does not recognise. Silently dropping
a node would silently drop a capability check.

## 3. Document

```json
{
  "irVersion": "0.1",
  "language": "0.1",
  "agent": "heptapus.examples.research.ResearchAgent",
  "doc": "A realistic research workflow.",
  "inputs":  { "topic": "string" },
  "outputs": { "report": "artifact<markdown>" },
  "types":   { "search_result": { "fields": [ { "name": "title", "type": "string" } ] } },
  "requirements": { "model": { "mode": "capabilities", "capabilities": ["tool_calling"] } },
  "tools":  [ { "ref": "mcp:web.search", "name": "web.search", "transport": "mcp",
                "effects": ["network"],
                "signature": { "params": [ { "name": "query", "type": "string" } ],
                               "result": "search_result[]" } } ],
  "state":  { "queries": "string[]" },
  "budget": { "steps": 60, "tokens": 120000, "cost": { "amount": "5", "currency": "usd" } },
  "policy": { "network": { "decision": "allow", "values": ["arxiv.org"] } },
  "effects": ["model_access", "network"],
  "entry": "n0",
  "nodes": []
}
```

| Field | Required | Meaning |
|-------|----------|---------|
| `irVersion` | yes | schema version |
| `language` | yes | language version of the source |
| `agent` | yes | fully qualified agent name |
| `doc` | no | doc comment from the source |
| `inputs` | yes | input name to type |
| `outputs` | yes | output name to `artifact<T>` |
| `types` | no | record types referenced by the program |
| `requirements` | yes | how to choose a model |
| `tools` | no | tools granted to this agent |
| `state` | no | working-memory field name to type |
| `budget` | yes | limits; may be empty |
| `policy` | yes | decision per subject; may be empty |
| `effects` | yes | union of effects the flow can trigger, sorted |
| `entry` | yes | id of the first node, or `null` |
| `nodes` | yes | every node, in creation order |

Empty collections are omitted rather than written as `{}` or `[]`, except
`budget` and `policy`, which are always present so a reader never has to
distinguish "absent" from "empty".

### 3.1 Model requirements

```json
{ "mode": "capabilities", "capabilities": ["structured_output", "tool_calling"],
  "contextTokens": { "min": 131072 } }
{ "mode": "exact", "reference": "openai/gpt-5" }
{ "mode": "unspecified" }
```

Capabilities are sorted. `unspecified` means the backend's default applies.

### 3.2 Budget

`steps` and `tokens` are integers. `cost.amount` is a **decimal string**:
binary floats round-trip differently across platforms and serializers, and a
reproducible artifact cannot depend on that.

One step is one `llm.call`, `tool.call` or `agent.call`.

### 3.3 Policy

```json
{ "network": { "decision": "allow", "values": ["arxiv.org", "github.com"] },
  "secrets": { "decision": "deny", "qualifier": "export" },
  "external_write": { "decision": "requireApproval" } }
```

Decisions: `allow`, `deny`, `requireApproval`. Subjects absent from this object
are **denied**. `values` is sorted and deduplicated.

A backend that cannot enforce a decision must report it as a portability loss
rather than proceeding: an unenforced `deny` is worse than a build failure.

## 4. Nodes

Every node has `id`, `kind` and `next`. `next` is the following node in the same
region, or `null` at the end of one. Ids are `n0`, `n1`, … in creation order.

| Kind | Purpose | Notable fields |
|------|---------|----------------|
| `llm.call` | model call | `prompt`, `responseType`, `args`, `binding` |
| `tool.call` | tool invocation | `tool`, `args`, `effects`, `binding` |
| `agent.call` | sub-agent call | `agent`, `args`, `effects`, `binding` |
| `branch` | two-way conditional | `condition`, `then`, `else` |
| `parallel` | bounded fan-out | `mode`, `source`, `binder`, `body`, `binding` |
| `loop` | bounded iteration | `maxIterations`, `guard`, `body` |
| `approval` | human approval gate | `label`, `effects` |
| `verify` | deterministic validation | `verifier`, `args` |
| `state.read` | read working memory | `field`, `binding` |
| `state.write` | write working memory | `field`, `value` |
| `artifact.emit` | produce an output | `output`, `value` |
| `checkpoint` | resumable boundary | `label` |

Fields that do not apply to a kind are omitted.

### 4.1 Regions

`then`, `else` and `body` hold the id of a region's first node. The region's
last node has `next: null`; control then returns to the node after the
container. Region nodes appear in the same flat `nodes` array as everything
else, and a region's nodes may have lower ids than their container — ids record
creation order, not execution order.

### 4.2 `parallel`

`mode` is `"map"`, the only fan-out in IR 0.1. The body runs once per element of
`source` with the element bound to `binder`. **The value of an iteration is the
result of the last node in `body`.** The container's `binding` receives the list
of those values.

Iterations are independent: the IR guarantees the body contains no state write,
no emission and no checkpoint.

### 4.3 `approval`

Inserted by the compiler, never written by a user. It precedes any call whose
effects include one the policy marks `requireApproval`, and its `effects` field
lists exactly those effects. A backend that cannot pause for approval must
refuse the artifact.

### 4.4 `state.read`

Reading working memory is a node, not an inline reference, so that state access
is visible in the artifact and a backend without state support fails at a
precise point. One node is emitted per field per statement; its `binding` has
the form `$state.<field>` and cannot collide with a source-level name.

## 5. Values

A value is a pure expression: evaluating it calls nothing and has no effects.

```json
{ "kind": "literal", "type": "int", "value": 8 }
{ "kind": "ref", "scope": "input", "path": ["topic"] }
{ "kind": "ref", "scope": "binding", "path": ["hit", "title"] }
{ "kind": "list", "items": [] }
{ "kind": "template", "parts": [] }
{ "kind": "unary", "op": "!", "operand": {} }
{ "kind": "binary", "op": ">=", "lhs": {}, "rhs": {} }
{ "kind": "builtin", "name": "len", "args": [] }
{ "kind": "unknown" }
```

`scope` is `input`, `binding` or `state`. `path[0]` is the root name; the rest
are record field accesses.

`unknown` appears only where the source failed to check. A successful build
never emits one, so a backend may treat it as a hard error.

### 5.1 Templates

A prompt with placeholders lowers to a template:

```json
{ "kind": "template", "parts": [
  { "kind": "text", "value": "Research: " },
  { "kind": "value",
    "value": { "kind": "ref", "scope": "input", "path": ["topic"] },
    "type": "string" } ] }
```

A prompt with no placeholders stays a plain string literal. Substitutions carry
their Ingot type so a backend knows how to render them.

## 6. Arguments

Call arguments are always named and always in the order the callee declares
them, even when the source passed them positionally. A backend never depends on
argument order in the source.

## 7. Reading an IR document

Minimal walk:

```
node = ir.entry
while node is not null:
    n = ir.nodes[node]
    handle(n)                       # descend into then/else/body as required
    node = n.next
```

Backends should reject, not skip: an unknown `kind`, an unknown `value.kind`, an
unsupported policy decision or an `irVersion` with a higher major version are all
reasons to stop. Skipping a node is how a capability restriction gets lost.
