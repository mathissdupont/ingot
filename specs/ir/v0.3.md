# Agent IR Specification, version 0.3

Status: **Draft, implemented**. Normative for `"irVersion": "0.3"`.

Agent IR 0.3 is Agent IR 0.2 plus one node kind, `consult`, and one effect,
`human`. Everything else — the document shape, values, arguments, policy and
budget rules, source spans, persistent memory — is inherited unchanged from
[Agent IR 0.2](./v0.2.md) and [Agent IR 0.1](./v0.1.md). The machine-readable
schema is [`agent-ir.schema.json`](./agent-ir.schema.json).

Designed in [RFC-0020](../../rfcs/0020-a-person-in-the-loop.md).

## 1. Versioning

`irVersion` is the schema version. A backend that implements major version `0`
may accept `0.1`, `0.2` and `0.3`.

**0.3 is the first minor version a 0.2 reader cannot safely accept in general.**
`sourceSpan` and `condition` were additive fields an older reader could ignore;
a node kind is not. A document containing a `consult` node describes work an 0.2
reader has no way to perform, so refusing it is correct and ignoring it is not.

A document that contains no `consult` node is identical in every other respect
to the 0.2 document the same source produced. Producers stamp the version they
implement rather than the lowest one a document happens to fit, because a
consumer's decision must not depend on inspecting every node first.

## 2. The `consult` node

A question put to a person, whose answer becomes a value the flow reads.

```json
{
  "id": "n3",
  "kind": "consult",
  "binding": "framing",
  "prompt": { "kind": "string", "value": "Which framing should the report take?" },
  "responseType": "string",
  "effects": ["human"],
  "args": [
    {
      "name": "choices",
      "value": { "kind": "list", "items": [
        { "kind": "string", "value": "technical" },
        { "kind": "string", "value": "executive" }
      ]}
    }
  ],
  "next": "n4"
}
```

| Field | Meaning |
|---|---|
| `prompt` | the question, a value like any other prompt |
| `responseType` | always `"string"` |
| `effects` | always exactly `["human"]` |
| `args.choices` | optional; a list of string values a person may pick from |
| `args.*` | anything else is context, shown to the person before they answer |
| `binding` | the name the answer is bound to |

### 2.1 What a runner must do

1. **Emit `consultationAsked` before asking**, carrying the node, the index, the
   question and the choices. The run then blocks. A surface watching the stream
   is how a person learns a question is waiting, so a runner that asked first and
   announced afterwards would leave a run that looks hung.
2. **Ask whoever the operator arranged.** How is not specified here: a terminal,
   a pipe, a page, or a recording all satisfy it.
3. **Refuse an answer that is not among `choices`**, when `choices` is present.
   The artifact stated what may come back; a channel is not a trusted source
   because a person is behind it.
4. **Emit `consultationAnswered`**, then bind the answer.

A failure at any step ends the run. There is no safe default: unlike an approval
gate, which has a known safe side, a question does not — so a runner must never
supply an answer nobody gave.

### 2.2 Steps and budgets

A `consult` consumes one step, like a model, tool or agent call. It consumes no
tokens and no money.

### 2.3 Where it may not appear

A `consult` node never appears inside a `parallel` body. The compiler refuses it
([Language 0.3 §1.4](../language/v0.3.md)), and a runner encountering one in a
malformed artifact may treat it as malformed IR.

## 3. The `human` effect

`human` joins the effect enumeration. It is policy-controlled under a subject of
the same name, and it takes no reach values.

A runner re-checks it against the artifact's policy exactly as it re-checks every
other effect: an artifact reaching a `consult` node whose policy does not grant
`human` is refused, whether or not the compiler that produced it said so.

`human require approval` is not expressible: the compiler refuses it
(`ING4011`), and an artifact carrying it is malformed.

## 4. Recording and replay

A run's questions and their answers are recorded in a third ordered list beside
the model exchanges and the tool calls. Matching is by position, then by a digest
of everything that determined the answer — the question, the choices, and the
context shown.

The three lists are matched independently. One interleaved stream would make each
side's position depend on the others', and it would lose the thing most worth
knowing about a recorded run: **which answers a machine produced and which a
person did.**

See [`ingot-runtime`'s cassette format](../../crates/ingot-runtime/src/cassette.rs),
cassette version 0.3.

## 5. Backends that cannot ask

A backend with no channel to a person must **refuse the artifact at build time**,
reporting `human` as unsupported, rather than accepting it and failing at the
node.

An artifact that builds and cannot run is the failure the effect system exists to
prevent, and a backend gets no exemption from it. The reference Python backend
does exactly this.
